# Для автора: как выпускать обновления

Друзья получают обновления командой `./ydl update` (или сами ночью, если они включили автообновление: по умолчанию оно выключено, потому что запускает код из вашего репозитория). Что делать вам:

1. Правите код в `app/` (`ydl.py`, `page.html`, `pwlogin.py`).
2. Поднимаете версию в файле `app/VERSION` (например `0.1.1`) и дописываете пункт в `CHANGELOG.md`.
3. `git commit` и `git push`.

Всё. При обновлении у друзей `git pull` заберёт изменения, образ пересоберётся, контейнер перезапустится; очередь, пароли ссылок, история и скачанные файлы лежат вне образа и сохраняются.

Если обновление меняет формат `state.json` (очередь), добавляйте в `ydl.py` совместимость при чтении: старые установки продолжат работать.

## Как проверить изменения у себя
```bash
docker compose build && docker compose up -d
./ydl logs
```
Страницу можно править «на горячую»: `app/page.html` читается при каждом запросе, но в контейнер он попадает при сборке образа.

## Если раздаёте архивом, а не через git
В `.env` у друзей: `YDL_UPDATE_URL=<ссылка на .tar.gz с последней версией>`. `./ydl update` сравнит `app/VERSION` и обновит файлы.

## Если когда-нибудь понадобится готовый образ
Соберите и выложите образ в реестр (GHCR/Docker Hub), у друзей в `.env` задайте `YDL_IMAGE=<образ>`: тогда `./ydl update` будет делать `docker compose pull`, без локальной сборки.

## Статус проекта (alpha / beta / stable)
Статус лежит в файле `app/STATUS` и показывается на странице, в установщике и в `./ydl info`. Пока там `alpha`, на GitHub отмечайте релизы галочкой **Pre-release**
и не убирайте предупреждение «на свой страх и риск» из README. Перейти на `beta`/`stable` можно, изменив содержимое файла.

## Выпуск образа в GitHub Container Registry (после публикации репозитория)
1. Поднимите `app/VERSION` (например `0.1.1`), допишите `CHANGELOG.md`, закоммитьте и отправьте в `main` (CI прогонит тесты и сборку).
2. Создайте тег, совпадающий с версией, и отправьте его: `git tag v0.1.1 && git push origin v0.1.1`.
3. Workflow `Release image` проверит тег, прогонит тесты и соберёт образ `ghcr.io/<владелец>/<репозиторий>` (`linux/amd64`, `linux/arm64`) с метками `0.1.1`, `0.1` и `latest`.
4. Один раз после первой публикации: GitHub → ваш профиль → Packages → образ → Package settings → **Change visibility → Public**
   (иначе `docker pull` у остальных потребует вход). Сборка для arm64 в этом репозитории автоматически не проверялась, посмотрите результат первого запуска.
5. Установщик по умолчанию берёт `ghcr.io/ferrykit/ydl:latest` (строка `YDL_IMAGE` в начале `install.sh`; в форке замените владельца). Пользователи обновляются `./ydl update`.

## Тесты
`python -m unittest discover -s tests -v` и `bash tests/test_shell.sh`. Они проверяют защиту путей и адресов, вход, CSRF/Host, раздачу файлов, удаление и архивы
(поднимая настоящий HTTP-сервер на свободном порту, ничего не трогая вне временной папки).
