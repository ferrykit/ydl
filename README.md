# ydl — выгрузка папок с Яндекс.Диска на свой сервер

**Русский** · [English](README.en.md) · Лицензия [MIT](LICENSE) · [Безопасность](SECURITY.md) · [Как помочь](CONTRIBUTING.md)

Если Яндекс.Диск плохо отдаёт данные (приложение «ползёт», WebDAV и rclone не работают, а скачать папку целиком из веба нельзя),
`ydl` забирает папки по **публичным ссылкам**: сам обходит структуру, качает несколько файлов параллельно, докачивает оборванное,
проверяет размер и MD5, не застревает на «больных» серверах Яндекса (пробует позже) и кладёт файлы на ваш сервер в тех же папках,
как на Диске. Работает и со ссылками **под паролем**. Управление — на веб-странице, в том числе с телефона.

> ⚠️ **Статус: alpha (ранняя версия).** Проект написан быстро и выпущен **«как есть»**. В нём могут быть ошибки и баги, часть возможностей может
> сломаться при изменениях на стороне Яндекса. Используйте **на свой страх и риск**: не храните на нём единственные копии данных, проверяйте результат,
> делайте резервные копии. Сроки исправлений и поддержка не гарантируются.

> **Неофициальный проект, не связан с Яндексом.** Предназначен для скачивания **ваших собственных** данных и данных, на которые у вас есть право;
> соблюдайте условия сервиса Яндекса и законодательство об авторском праве. Подробнее: раздел «Дисклеймер» внизу.

## Что нужно
- Компьютер или сервер с **Linux** (подойдёт и домашний мини-ПК/NAS), включённый на время выгрузки.
- **Docker** с `docker compose` версии 2+. **Ставить его заранее не нужно**: если Docker нет, установщик предложит поставить его сам (на Ubuntu/Debian из репозитория системы, на других Linux официальным скриптом Docker) и запустит. Нужен только пользователь с `sudo` или root.
- Свободное место под ваши файлы (скрипт установки покажет, сколько где есть).
- Доступ к вашему Яндекс.Диску, чтобы включить публичные ссылки на нужные папки.

## Установка

Зайдите на сервер по ssh и выполните две команды:
```bash
git clone https://github.com/ferrykit/ydl && cd ydl
./install.sh
```
Первая команда скачивает проект, вторая запускает установщик, который скачает готовый образ. Больше ничего собирать не нужно.
(Если на сервере нет `git`: `sudo apt-get install -y git`.)

Установщик задаст несколько вопросов; на каждый можно просто нажать Enter. Если Docker не найден, он сам предложит его поставить:
1. **Где будет работать ydl**: дома (без шифрования), на сервере в интернете (VPS) с HTTPS по IP или с доменом и HTTPS. Вариант по умолчанию подбирается по адресу сервера, подробнее в разделе «HTTPS»;
2. **Куда скачивать файлы**: покажет диски со свободным местом и предложит папку `~/ydl-downloads`;
3. **Порт** страницы (только для варианта «дома»; по умолчанию 8085, если занят подберёт следующий);
4. **Слоты** (одновременные скачивания, по умолчанию 8);
5. **Пароль** на страницу: закрывать ли её паролем (рекомендуется) и какой. Можно ответить «нет», а включить позже;
6. **Автообновление** по ночам (по умолчанию выключено, см. «Обновление»).

Потом скачает образ (около минуты), запустит сервис, дождётся, пока он ответит, и в конце покажет:
- **ссылку для браузера** отдельной строкой, с правильным портом (если порт по умолчанию был занят, подберётся свободный и в ссылке будет именно он);
- **пароль**, который вы задали (запишите его);
- папку для файлов и число слотов.

Эту ссылку можно показать снова в любой момент: `./ydl info`.

**Откройте страницу**, адрес покажет установщик, например `http://192.168.1.50:8085`. Если вы включили пароль, откроется страница входа: введите пароль (логина нет). Вход запоминается на этом устройстве на 30 дней, кнопка «Выйти» есть в шапке.

> Дома страница открывается с компьютера или телефона из той же сети. Если сервер **в интернете (VPS)**, выберите в установщике
> вариант с HTTPS (по IP или домену): так и пароль, и файлы защищены. Подробнее в разделе «HTTPS».

## Как пользоваться

1. **На Яндекс.Диске** создайте публичную ссылку на каждую нужную папку (подробно: «Как создать ссылку на Яндекс.Диске» ниже).
2. **На странице ydl** нажмите «Добавить ссылки». Каждой ссылке своя строка с двумя полями: **ссылка** и **пароль** (пароль нужен, только если он есть у ссылки). Как только заполнена последняя строка, ниже сама появляется пустая. Если вставить в поле сразу несколько ссылок (каждая с новой строки), они разложатся по строкам. Нажмите «Добавить»: если какая-то ссылка не принята, её строка подсветится красным с причиной, остальные добавятся.
3. Подождите, пока сервис проверит ссылку и получит список файлов (статус «выбор файлов»).
4. Нажмите **«Выбрать файлы»**, снимите галочки с ненужного → **«Сохранить и в работу»**. Скачивание само не стартует, пока вы не нажмёте.
5. Следите за прогрессом на странице. Закрывать страницу и выключать свой компьютер можно, всё работает на сервере.
6. Когда статус **«готово»** — **закройте публичную ссылку на Яндекс.Диске** и проверьте файлы.

> **Не публикуйте** папки с ключами и паролями (например `.ssh`) и не оставляйте ссылки открытыми дольше нужного.

### Как создать ссылку на Яндекс.Диске
`ydl` забирает данные **по публичным ссылкам**: ссылку на весь Диск целиком Яндекс создать не даёт, поэтому ссылки нужны **отдельно на каждую папку**, а для файлов, лежащих прямо в корне Диска, отдельно на каждый файл или одна ссылка на папку, в которую вы их предварительно перенесли.

1. Откройте свой Диск в браузере ([disk.yandex.ru](https://disk.yandex.ru) или Яндекс 360).
2. Выделите **папку** (клик по ней, не заходя внутрь) и нажмите **«Поделиться»** (в меню «…» или на верхней панели). Включите доступ по ссылке («Доступ по ссылке», «Включить доступ») и нажмите **«Копировать ссылку»**. Ссылка выглядит так: `https://disk.yandex.ru/d/AbCdEf...` (или `disk.360.yandex.ru/d/...`).
3. Повторите для **каждой** папки, которую хотите забрать. Вложенные папки отдельно не нужны: ссылка на папку включает всё внутри.
4. **Файлы в корне Диска** (не в папках): либо сделайте ссылку на каждый такой файл так же, как на папку, либо создайте на Диске новую папку, перенесите в неё эти файлы и сделайте одну ссылку на неё. Второй способ быстрее, если файлов много.
5. Вставьте все ссылки в `ydl` (см. выше). Ссылка на подпапку внутри уже расшаренной папки не подходит: нужна ссылка именно на ту папку, где вы включили доступ.
6. **Безопасность.** Публичная ссылка открывает папку любому, у кого она есть. Если на вашем тарифе есть **пароль на ссылку** и **срок действия**, включите их (срок 1–7 дней достаточно) и вводите пароль в поле рядом со ссылкой. Не делайте ссылки на папки с ключами и паролями (например `.ssh`). **Когда статус «готово», закройте ссылку на Яндексе** («Закрыть доступ»).

Название кнопок на Яндекс.Диске время от времени меняется, но порядок тот же: выделить папку, «Поделиться», доступ по ссылке, скопировать.

### Кнопки на главной странице
- **Добавить ссылки**: форма со строками «ссылка + пароль».
- **Файлы**: файловый менеджер (просмотр, скачивание, архивы, удаление).
- **Пауза / Продолжить**: общая пауза всех загрузок. При нажатии новые файлы не берутся в работу, а скачиваемые прямо сейчас останавливаются в пределах секунды (недокачанное сохраняется, при «Продолжить» докачивается с того же места). Пауза сохраняется даже после перезапуска сервиса. На паузе по-прежнему можно добавлять ссылки, выбирать файлы и собирать архивы. Остановить только одну ссылку можно кнопкой «Остановить» на её карточке.
- **Выйти**: выход на этом устройстве (кнопка есть, только если включён пароль).
- **Тема**: авто / светлая / тёмная.

## Куда сохраняются файлы и как их забрать

### Куда
Выбирается при установке и хранится в файле `.env` в переменной `YDL_DOWNLOADS`. Структура внутри:
```
<папка для файлов>/
  Название папки с Яндекс.Диска/
    подпапки/и/файлы
```
Узнать путь: `./ydl where`. Как выбрать:
- **Простой вариант** — `~/ydl-downloads` в домашней папке: подходит, если там достаточно места.
- **Отдельный диск или NAS** — укажите путь к нему (`/mnt/disk2/ydl`, `/srv/storage/yandex`). Если у вас сетевая папка, **сначала смонтируйте её** на сервере и укажите путь к точке монтирования.
- **Места не хватит?** Объём папок виден на Диске заранее. Нужно примерно столько же свободного места плюс запас.

Поменять папку позже: перенесите уже скачанное (`mv`), поправьте `YDL_DOWNLOADS` в `.env` и выполните `./ydl start`. Прогресс сохранится: файлы, которые уже на месте, повторно не качаются.

### Как забрать файлы себе
1. **Из браузера: кнопка «Файлы» на странице.** Это файловый менеджер:
   - ходите по папкам, ищите по имени (в этой папке или «Искать везде»), сортируйте по имени, размеру, дате;
   - **кликните по файлу, он скачается** (докачка при обрыве работает);
   - отметьте галочками папки и файлы (или откройте нужную папку) и нажмите **«Архивировать»**: сервис соберёт один `.zip` **рядом с исходной папкой** (например, папка «Фото» → архив «Фото.zip» в той же папке, где лежит «Фото»);
   - ход сборки виден сверху страницы («собирается: 43%…»). Готовый архив остаётся на диске как обычный файл: его можно **скачивать сколько угодно раз**, а когда он не нужен, нажать «Удалить архив»;
   - перед сборкой проверяется свободное место; если его не хватает, архив не начнут собирать и объяснят почему;
   - можно создать новую папку (кнопка «＋ Папка»).

   - **удалить** выбранное с сервера, чтобы освободить место (подробнее ниже).
2. **По сети (очень много файлов):**
   - Mac/Linux: `rsync -avP пользователь@адрес-сервера:/путь/к/ydl-downloads/ ./куда-у-вас-дома/`
   - Windows: [WinSCP](https://winscp.net) (протокол SFTP, тот же логин и пароль, что для входа на сервер по SSH).
   - Mac: [Cyberduck](https://cyberduck.io) или `scp -r`.
3. **Если сервер — ваш домашний ПК или NAS:** просто откройте папку из `YDL_DOWNLOADS` или расшарьте её средствами системы (Samba/NFS).

### Как освободить место (и качать по частям)
Если места не хватает на всё сразу, качайте **по частям**: скачали часть, забрали себе, удалили с сервера, взяли следующую.
1. Заберите скачанное себе: в разделе «Файлы» отметьте папки или файлы, нажмите **«Архивировать»** и скачайте готовый `.zip` (или скопируйте по сети через `rsync`).
2. Убедитесь, что копия у вас открывается.
3. Отметьте то же самое и нажмите **«Удалить»**. Откроется окно: размер, список и галочка «Я скопировал(а) нужное себе». Без неё кнопка «Удалить навсегда» не нажимается.
4. Удалите и сам архив (кнопка «Удалить архив»), он занимает столько же места, сколько папка.

Что происходит при удалении, чтобы `ydl` не скачал всё заново:
- удалили **файл или подпапку внутри** папки ссылки: они **исключаются из загрузки** (в «Выбрать файлы» на главной видно «Исключено вами»); вернуть можно там же, тогда файлы скачаются снова;
- удалили **папку ссылки целиком**: ссылка убирается из списка.

Удаление необратимо: корзины нет. Оно действует только внутри папки данных `YDL_DOWNLOADS`.

> Архивы лежат внутри папки данных и занимают место (сжатия нет: фото, видео и так сжаты, зато быстро). Если вы копируете папку данных целиком (`rsync`), готовые архивы тоже скопируются.

## HTTPS (шифрование)
Без HTTPS пароль и файлы идут по сети открытым текстом. Дома, в своей сети, это обычно не страшно. А вот **на сервере в интернете (VPS) HTTPS нужен обязательно**.

**Как это работает (минимум).** Браузер показывает замок, если сертификат подписан организацией из его встроенного списка (Let's Encrypt в нём есть) и выдан именно на тот адрес, который вы набрали. Перед подписью организация проверяет, что адрес ваш: обращается к нему **из интернета** через порты 80 и 443. Отсюда два следствия:
- у сервера с **публичным IP** или **доменом** сертификат получить можно, это бесплатно и автоматически;
- у домашнего адреса вида `192.168.x.x` публичный сертификат получить нельзя (до него из интернета не достучаться). «Домашний» сертификат пришлось бы устанавливать вручную на каждое устройство, чтобы браузер не ругался, поэтому в `ydl` такого режима нет: дома страница работает по обычному `http`.

**Три режима** (выбираются в установщике, менять потом можно командой):

| Режим | Когда | Адрес | Команда |
|---|---|---|---|
| Дома, без шифрования | сервер в вашей домашней сети | `http://192.168.x.x:8085` | `./ydl https off` |
| **VPS по IP** | сервер в интернете с публичным IP, домена нет | `https://45.x.x.x` | `./ydl https ip` |
| **Домен** | есть домен, он указывает на сервер | `https://ydl.example.com` | `./ydl https domain ydl.example.com` |

### Как подключить свой домен
Домен (или поддомен, например `ydl.example.com`) можно купить у любого регистратора. Нужно один раз сказать DNS, что имя ведёт на ваш сервер:
1. В панели DNS регистратора добавьте запись типа **A**: имя `ydl` (для поддомена; для самого домена `@`), значение это **публичный IP сервера** (его показывает установщик, или команда `curl https://api.ipify.org` на сервере). Время жизни (TTL) поставьте поменьше, например 300 секунд.
2. Если у домена есть запись **AAAA** (IPv6), удалите её или направьте на этот сервер: Let's Encrypt проверяет и по IPv6, и чужая AAAA ломает выпуск. Установщик об этом предупредит.
3. Если домен у вас в **Cloudflare**, поставьте для этой записи режим «только DNS» (серое облако). С оранжевым облаком Cloudflare встанет между вами и Let's Encrypt, и выпуск может не пройти.
4. Запустите установщик и выберите вариант 3, либо на уже установленном сервисе: `./ydl https domain ydl.example.com`. Он проверит, что имя ведёт на этот сервер. Если запись ещё не «разошлась» по DNS (это занимает от минуты до часа), предложит **подождать до 10 минут**. Потом сам получит сертификат.
5. Откройте `https://ydl.example.com` (порт указывать не нужно).

Сменить домен: `./ydl https domain другой.example.com`. Вернуться к адресу по IP: `./ydl https ip`.
**Сервер дома, домен хочется?** Нужен проброс портов 80 и 443 на роутере к серверу, а A-запись должна вести на ваш внешний IP (если он у провайдера меняется, понадобится динамический DNS). Если всё это звучит как лишнее, оставьте обычный HTTP: дома шифрование обычно не нужно.

**Что нужно для HTTPS** (VPS по IP и домен):
- порты **80 и 443** свободны на сервере и открыты в файрволе (у провайдера, если он есть отдельно, и в `ufw`: установщик откроет их в `ufw` сам, если тот включён);
- для домена: A-запись у регистратора указывает на IP сервера (установщик это проверит и предупредит);
- для IP: адрес должен быть публичным и **постоянным**. Если провайдер сменит IP, выполните `./ydl https ip` ещё раз.

**Что, если порты заняты.**
- **Порт 80 занят** другой программой (например, у вас на сервере уже работает сайт на nginx): это не помеха. `ydl` оставит порт 80 ей и поднимет HTTPS **только на порту 443**; Let's Encrypt подтверждает адрес через 443 (способ TLS-ALPN). Установщик сообщит об этом. Минус один: адрес `http://…` не будет перенаправляться на HTTPS, на нём продолжит отвечать та программа. Если позже порт 80 освободится, выполните `./ydl https ip` ещё раз, и `ydl` вернётся к обычному режиму.
- **Сертификат не выдался.** Установщик покажет причину («Почему нет сертификата»). Частые случаи: порты 80/443 закрыты в файрволе (в том числе у провайдера); домен не указывает на этот сервер; провайдер блокирует исходящие соединения к Let's Encrypt (тогда нужен другой сервер или дата-центр); **лимит Let's Encrypt: не больше 5 сертификатов в неделю на один и тот же адрес**. Из-за лимита не стоит многократно переустанавливать ydl на один IP и удалять тома Docker (`docker volume rm`): в них лежит выданный сертификат. При упоре в лимит Caddy сам повторит попытку, когда он снимется. Причина всегда видна в `./ydl logs caddy` (выход из просмотра: Ctrl+C).
- **Порт 443 занят**: HTTPS невозможен (он нужен обязательно). Установщик предложит продолжить без HTTPS (страница будет работать по `http://адрес:8085`) или остановиться, чтобы вы освободили порт.
- Если порт заняли **после** установки и Caddy не смог запуститься, страница снаружи станет недоступна (она закрыта только внутрь сервера). Команда `./ydl status` покажет предупреждение «HTTPS не работает: Caddy не запущен»; причину смотрите в `./ydl logs caddy`. Быстрый выход: `./ydl https off` вернёт страницу на `http://адрес:8085`.

**Какой адрес открывать.** При HTTPS адрес **без порта**: `https://45.x.x.x` (порт 443 подразумевается). Адрес вида `https://45.x.x.x:8085` не работает никогда: порт 8085 это обычный HTTP без шифрования, а в режимах HTTPS он к тому же закрыт снаружи. Актуальный адрес всегда показывает `./ydl info`.

**Особенности сертификата на IP.** Let's Encrypt выдаёт такие сертификаты на **6 дней** (для доменов 90). Продлевает их автоматически служба Caddy, которая запускается рядом с `ydl`: нужно только, чтобы порты 80 и 443 (или хотя бы 443, если 80 занят) оставались открытыми. Выпуск занимает секунды. Проверено на реальном сервере.

**Что меняется в режимах HTTPS:** `ydl` перестаёт слушать наружу (порт 8085 доступен только с самого сервера), весь трафик идёт через Caddy, у cookie входа появляется флаг `Secure`, а блокировка подбора пароля видит настоящий IP клиента. HTTP-адрес перенаправляется на HTTPS.

Состояние: `./ydl https`. Если сертификат не выдаётся: `./ydl logs caddy` (частые причины: порты 80/443 закрыты у провайдера, домен ещё не указывает на сервер).

## Пароль: включить, сменить, сбросить, отключить
Пароль защищает страницу входом (одно поле, без логина). Управляется командами на сервере, старый пароль знать **не нужно**:
```bash
./ydl password              # включить пароль или сменить на новый случайный (он будет показан)
./ydl password мойНовый     # задать свой
./ydl password --off        # отключить пароль (вход без пароля, только для домашней сети)
```
Перезапускать ничего не надо. После смены пароля все устройства нужно войти заново. Если пароль вводят неверно 5 раз подряд, вход с этого адреса временно блокируется (30 секунд, потом дольше). Если пароль при установке не включали, страница открывается без входа, пока вы не выполните `./ydl password`.

## Обновление
Версия показана внизу страницы и командой `./ydl version`.
```bash
./ydl status                # есть ли новая версия
./ydl update                # обновить (очередь, файлы и пароли сохраняются; скачивание продолжится)
./ydl autoupdate on         # обновляться само каждую ночь в 04:00 (off — выключить)
```
Что изменилось в версиях: [CHANGELOG.md](CHANGELOG.md).

## Слоты: что это и сколько ставить
**Слот** это одно параллельное скачивание: сервис берёт один файл и качает его по отдельному соединению. 8 слотов значит, что одновременно идёт до 8 файлов. На главной странице блок «Слоты заняты» показывает, чем занят каждый слот («подключаюсь», «получаю данные», «данные встали», «свободен»). Если одновременно качается несколько ссылок, на одну ссылку приходится не больше 3 слотов, чтобы одна большая папка не заняла всё.

Число слотов выбирается при установке (по умолчанию 8). Поменять потом: `./ydl slots 6` (очередь и докачка сохраняются) или `YDL_SLOTS` в `.env`.

**От чего зависит, сколько ставить**
- **Скорость вашего интернета.** Одно «здоровое» соединение с Яндексом давало у нас 5–13 МБ/с (40–100 Мбит/с). Значит, на домашнем канале около 100 Мбит/с хватает 2–3 слотов, остальные лишь ждут. Больше слотов скорость выше канала не поднимет.
- **Сбои на стороне Яндекса.** Часть серверов хранилища Яндекса «молчит»: слот, попавший на такой файл, до 30 секунд ждёт данных зря. Лишние слоты в это время продолжают качать другое, поэтому запас слотов сверх «нужного для канала» полезен. Отсюда 8 по умолчанию.
- **Осторожность с Яндексом.** Чем больше слотов, тем больше одновременных запросов. Если Яндекс начинает просить притормозить («Яндекс просит притормозить» в журнале, длинные паузы всех слотов), слотов слишком много: поставьте 4.
- **Ваш сервер.** Нагрузка на процессор и память маленькая. Диск обычно не узкое место, если это не очень медленная флешка или сетевая папка: тогда не больше 4.

**Ориентиры** (это прикидки по логике выше, а не замеры на разных каналах):

| Ваш интернет | Слотов |
|---|---|
| до 50 Мбит/с, или слабый сервер/сетевой диск | 3–4 |
| 100–300 Мбит/с | 6–8 (по умолчанию 8) |
| от 500 Мбит/с | 8–12 |
| больше 16 | не рекомендуем: выигрыша почти нет, риск, что Яндекс начнёт тормозить |

**Как понять, что слотов достаточно.** Откройте главную страницу во время скачивания. Скорость близка к скорости вашего канала, а в блоке слотов часть «свободна» или «получаю данные»: слотов хватает, можно уменьшить. Скорость маленькая, а слоты почти все «подключаюсь» или «данные встали»: узкое место Яндекс (его серверы молчат), а не число слотов; прибавка слотов помогает слабо, ждите восстановления.

### Как сервис выбирает, что качать первым
Пока Яндекс отдаёт данные нормально, файлы идут по порядку: мелкие первыми. Когда часть серверов Яндекса начинает «молчать», сервис включает **разведчика**: он заранее (по одному файлу раз в 2 секунды, лёгкими запросами) узнаёт, на каком сервере Яндекса лежит каждый из ближайших файлов. Файлы на серверах, с которых только что успешно скачали, ставятся **первыми**, файлы на молчащих серверах откладываются до их восстановления, остальные идут как раньше. В спокойное время разведчик ничего не делает и лишних запросов не создаёт. Выключить: `YDL_SCOUT=0` в `.env`.

## Частые вопросы
- **Ссылка получает ошибку «HTTP 404: ссылка закрыта?»** — публичная ссылка отключена или удалена на стороне Яндекса. Включите её заново.
- **«Пароль не принят»** — проверьте пароль ссылки, повторите кнопкой «Проверить пароль» на карточке.
- **«⚠ не отдаётся» у файлов** — Яндекс временно не отдаёт данные с части своих серверов. Это нормально: повторы идут сами, файлы добираются по мере восстановления. Совсем нужный файл можно скачать вручную из браузера.
- **Скорость маленькая или «ждём Яндекс»** — так ведёт себя Яндекс. Раскрыв «Что значат статусы» на странице, можно понять причину. Уменьшение `YDL_SLOTS` обычно не помогает ускорить, но снижает «нагрузку» на ссылку.
- **Порт занят** — `./ydl stop`, поменяйте `YDL_PORT` в `.env`, `./ydl start`.
- **`permission denied` при запуске docker** — `sudo usermod -aG docker $USER`, затем перелогиньтесь.
- **Кончилось место** — освободите его или перенесите папку (см. выше); сервис продолжит с того же места.

## Безопасность
Что защищено и как (подробнее и о том, как сообщить об уязвимости: [SECURITY.md](SECURITY.md)):
- **Вход по паролю** (если включён): пароль хранится в виде хэша, 5 неверных попыток подряд блокируют вход с адреса, сессия подписана и привязана к паролю.
- **Защита от подделки запросов:** все изменяющие запросы принимаются только от самой страницы ydl (проверяются заголовок `X-YDL`, `Origin` и `Sec-Fetch-Site`), поэтому открытый в браузере чужой сайт не может, например, удалить ваши файлы, даже если пароль отключён.
- **Защита от подмены адреса (DNS-rebinding):** запросы принимаются только с «своим» адресом в заголовке Host: IP, `localhost`, короткое имя, `*.local`/`*.lan` или имя из `YDL_ALLOWED_HOSTS`/домен HTTPS. Если вы открываете ydl по иному имени и видите «Недопустимый адрес в заголовке Host», добавьте его в `YDL_ALLOWED_HOSTS` в `.env` и выполните `./ydl start`.
- **Скачанные файлы не могут навредить сервису:** в браузере открываются только картинки, аудио, видео, PDF и обычный текст, а HTML, SVG, XML и всё неизвестное только скачиваются (в «песочнице»). Иначе файл из чужой папки мог бы выполнить скрипт от имени ydl.
- Скачивание идёт только с адресов Яндекса по HTTPS; имена папок с Яндекса не могут вывести запись за пределы папки загрузок.
- Контейнеры работают с файловой системой только для чтения, без привилегий, сервис от обычного пользователя (не root).
- **Ссылки на скачивание файлов и архивов не секретные адреса:** это обычные пути вида `/files/Папка.zip`, их легко угадать, поэтому защита держится на входе. Без входа сервер не отдаёт ни файлы, ни архивы, ни списки (проверено). Поэтому **включайте пароль** и не пересылайте адреса «на авось»: они откроются только тому, кто вошёл.
- Подбор пароля ограничен, но простой пароль вроде `1234` подобрать можно: используйте длинный. Автоматически созданный (16 символов) подобрать нельзя.
- Если пароль отключён (`./ydl password --off`), файлы доступны всем, кто видит порт. Дома это допустимо, в интернете нет.
- Дома страница работает по обычному HTTP, а на сервере в интернете **включайте HTTPS** (`./ydl https ip` или с доменом): иначе пароль и файлы видны по пути следования. См. раздел «HTTPS».
- **Автообновление** (`./ydl autoupdate on`) каждую ночь скачивает и запускает новый код из источника, откуда вы взяли ydl. Включайте его, только если доверяете автору; по умолчанию выключено.
- Пароли от ваших ссылок хранятся на сервере в томе Docker `ydl-config` в открытом виде (иначе их нельзя использовать) и не показываются на странице.
- `./ydl stop` + `docker compose down -v`: остановить и **стереть** очередь, пароли ссылок и историю (скачанные файлы остаются).
- Сервис забирает только то, что вы сами открыли по публичной ссылке, и не обходит ограничения Яндекса.
