# История версий

## 0.1.0 (alpha, первый публичный выпуск)
- Нумерация начата заново: всё, что было до этого (1.0.0–1.6.2), — внутренние версии, до публикации. Содержимое выпуска совпадает с внутренней 1.6.2.
- Статус alpha: выпущено как есть, использование на свой страх и риск (см. README).
- Если вы ставили внутреннюю сборку 1.x: `./ydl update` по `YDL_UPDATE_URL` сравнивает версии как строки и обновится на 0.1.0.

## 1.6.0 (безопасность и надёжность)
- Закрыта хранимая XSS: скачанные HTML/SVG/XML больше не открываются в браузере от имени сервиса (только скачивание, плюс CSP `sandbox` и `nosniff`).
- Защита от CSRF и DNS-rebinding: изменяющие запросы принимаются только от самой страницы (заголовок `X-YDL`, `Origin`, `Sec-Fetch-Site`), запросы с чужим именем в Host отклоняются (`YDL_ALLOWED_HOSTS`).
- Имя папки с Яндекса очищается перед использованием в пути; скачивание только по HTTPS с адресов Яндекса (включая перенаправления).
- Защитные заголовки (X-Frame-Options, CSP frame-ancestors, nosniff, Referrer-Policy, no-store); лимит размера запросов и таймаут соединений.
- Загрузка приостанавливается при нехватке места на диске (`YDL_MIN_FREE_GB`, по умолчанию 2 ГБ), на странице баннер.
- Надёжность: атомарная запись состояния, копия `state.json.corrupt` вместо затирания при повреждении, сохранение состояния при `docker stop`, нормализация путей `..` в менеджере файлов, исправлен вход с паролем из `.env` с кириллицей.
- Контейнеры: файловая система только для чтения, без привилегий, `init`, `no-new-privileges`; Caddy закреплён на `2.11`. Если установщик запущен от root, сервис всё равно работает от обычного пользователя (uid 1000).
- Установщик: проверяет пароль, домен и папку на допустимые символы (раньше `$` в пароле ломал `.env`), не показывает старый пароль при повторном запуске, автообновление по умолчанию выключено, не обращается к внешним сервисам за IP, пока это не нужно.

## 1.5.0
- Установщик сам проверяет Docker и ставит его, если нет (Ubuntu/Debian из репозитория системы, на других Linux официальным скриптом); добавляет пользователя в группу docker и продолжает установку без перезахода.
- HTTPS: рядом запускается Caddy. Режимы: дома без шифрования, VPS по IP (сертификат Let's Encrypt на IP на 6 дней, продлевается сам), домен. Выбор в установщике (по умолчанию подбирается по адресу сервера), смена командой `./ydl https ip|domain ИМЯ|off`. При HTTPS приложение слушает только внутри, cookie получает флаг `Secure`, блокировка подбора пароля считает реальный IP клиента.
- Режим домена: установщик и `./ydl https domain` проверяют, что имя ведёт на сервер, предлагают подождать до 10 минут, пока обновится DNS, и предупреждают про чужую AAAA-запись (IPv6).
- Порт 80 занят чужой программой: HTTPS всё равно работает на одном порту 443 (подтверждение сертификата через TLS-ALPN); порт 443 занят: установщик предлагает продолжить без HTTPS. `./ydl status` предупреждает, если Caddy не запущен.
- Установщик проверяет, что порты свободны, домен указывает на сервер, и открывает нужные порты в `ufw`, если он включён; ждёт выдачи сертификата и показывает итог.

## 1.4.2
- Финал установки: ссылка для браузера отдельной строкой с реальным портом (в том числе подобранным, если порт занят), пароль, ожидание запуска сервиса, подсказки про файрвол и копирование файлов. Адреса докера в ссылках не показываются.
- Команда `./ydl info` показывает адрес страницы и основные настройки в любой момент.

## 1.4.1
- Сообщение о паузе при ответе Яндекса 503 теперь честное: это временный сбой на стороне Яндекса (пауза 30 с, без нарастания), а не «блокировка с удвоением до часа». Для 429 текст прежний.

## 1.4.0
- Приоритет здоровым узлам Яндекса: файлы на серверах, с которых недавно успешно скачали, идут первыми; «разведчик» заранее узнаёт узлы ближайших файлов, но только пока Яндекс сбоит (`YDL_SCOUT=0` выключает).
- Слоты: вопрос при установке, команда `./ydl slots N`, раздел «Слоты» в README с ориентирами.
- Подпись «Свободно на диске загрузок» вместо жёстко прописанного «RAID1» (папка загрузок видна во всплывающей подсказке).

## 1.3.1
- Кнопка «Файлы» без подчёркивания, иконки у «Файлы» и «Выйти», подсказка у «Пауза».
- README: как создать публичные ссылки на Яндекс.Диске (по каждой папке и файлам в корне) и что делают кнопки.

## 1.3.0
- Добавление ссылок через строки «ссылка + пароль»: пустая строка появляется сама, вставка нескольких ссылок раскладывается по строкам; по каждой ссылке показывается результат, неверные не пропадают молча.
- Удаление в «Файлах» для освобождения места (с подтверждением): согласовано с очередью, удалённое исключается из загрузки, удаление папки ссылки убирает ссылку из списка.

## 1.2.0
- Файловый менеджер вместо простого просмотра: навигация, поиск (в папке и везде), сортировка, выбор галочками, новая папка.
- Архивы: выбранное или целая папка собирается в `.zip` рядом с исходной папкой, прогресс виден на странице, готовый архив можно скачивать повторно и удалить (удалять можно только свои архивы).

## 1.1.0
- Вход через страницу с паролем вместо окна браузера; без логина. Сессия 30 дней, кнопка «Выйти», блокировка при подборе пароля.
- Пароль можно не включать при установке, а включить, сменить или отключить позже: `./ydl password`.

## 1.0.0
- Первая версия в Docker: установка одной командой, настройка через `.env`.
- Папка для файлов выбирается при установке; установщик показывает свободное место.
- Пароль на страницу; смена и сброс командой `./ydl password`.
- Раздел «Файлы»: просмотр и скачивание скачанного из браузера.
- Обновление командой `./ydl update` и по ночам (`./ydl autoupdate on`).
- Страница лучше выглядит на телефоне.
